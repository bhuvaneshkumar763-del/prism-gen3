# Safari (macOS + iOS/iPadOS)

Safari doesn't load a raw web-extension folder the way Chrome/Firefox do —
since Safari 14 it requires the extension wrapped in a native app, built
with Xcode. `Prism/` is that wrapper: a real Xcode project generated by
Apple's own `xcrun safari-web-extension-converter`, containing the exact
same engine/UI code as the Chrome and Firefox builds (`wxt build -b safari`
output, copied in verbatim — see "Keeping it in sync" below).

## What's verified, concretely

Both targets **build and run for real**, not just "should work in theory":

- `Prism (macOS)` — builds and code-signs successfully with a real Apple
  Development certificate (`security find-identity` on the machine this was
  set up on), no manual Xcode signing configuration needed.
- `Prism (iOS)` — builds for the iOS Simulator, installs (`xcrun simctl
  install`), launches (`xcrun simctl launch`), and shows Prism's real icon
  and Apple's own "You can turn on Prism's Safari extension in Settings."
  prompt — confirmed via a real simulator screenshot, not assumed.

Both builds have `DEVELOPMENT_TEAM` baked into every build configuration in
`Prism.xcodeproj/project.pbxproj`, using the Apple ID/team already signed
into Xcode on the machine this was generated on. **If you clone this repo on
a different machine (or use a different Apple ID), open the project in
Xcode, select each target's "Signing & Capabilities" tab, and pick your own
team** — the baked-in team ID will show as invalid/inaccessible otherwise.
This is expected and not a bug; it's exactly the situation Xcode's own
"Signing & Capabilities" pane exists to fix.

## What isn't done, and can't be done by an agent

- **Real distribution.** A free/personal Apple ID (what's configured here)
  can sign and run this locally on your own Mac/Simulator. Actually
  distributing it — even outside the App Store, via Developer ID
  notarization — needs the **paid Apple Developer Program** ($99/yr), which
  needs your own payment details and Apple ID. Listing it on the App Store
  needs App Store Connect (screenshots, review, your own account).
- **Enabling the extension in Safari.** Apple requires a real, manual user
  gesture to turn on a Safari Web Extension — Safari → Settings →
  Extensions (macOS) or Settings → Apps → Safari → Extensions (iOS) — and
  this cannot be scripted or automated by design, regardless of tooling.
  Run the app once, then flip it on there.

## A real compatibility gap this setup already accounts for

Apple's converter itself warns: *"Persistent background pages are not
supported on iOS and iPadOS."* WXT's MV2 manifest (shared with the Firefox
build) doesn't set `background.persistent`, which defaults to `true` —
fine for Firefox, not fine for iOS Safari. `scripts/sync-safari.mjs` forces
`background.persistent: false` on the copy it hands to Xcode (universally,
not just for iOS — the codebase's `entrypoints/background.ts` already
assumes a background context that can be torn down and rebuilt on wake,
the same MV3-service-worker model Chrome uses, so this is the more correct
setting on macOS too, not a compromise). See that script's own comments for
the full reasoning.

## Keeping it in sync

The web extension itself is 100% the WXT build output. After changing
anything in `src/`, `entrypoints/`, or `components/`, resync it into the
Xcode project:

```bash
npm run safari:sync
```

This runs `wxt build -b safari`, then mirrors `.output/safari-mv2/` into
`safari/Prism/Shared (Extension)/Resources/` and re-applies the
`persistent: false` fix above. It does **not** touch anything else in the
Xcode project (build settings, the Swift wrapper files, asset catalogs) —
deliberately: `xcrun safari-web-extension-converter --rebuild-project` was
tested directly and found to fully regenerate the whole project from
scratch, discarding the baked-in signing team and any future hand-edits to
the native wrapper. A plain resource mirror is the correct, minimal
operation here.

## Building/running

```bash
open safari/Prism/Prism.xcodeproj
```

Or headlessly:

```bash
xcodebuild -project "safari/Prism/Prism.xcodeproj" -scheme "Prism (macOS)" build
xcodebuild -project "safari/Prism/Prism.xcodeproj" -scheme "Prism (iOS)" \
  -destination 'platform=iOS Simulator,name=<a simulator you have>' build
```
