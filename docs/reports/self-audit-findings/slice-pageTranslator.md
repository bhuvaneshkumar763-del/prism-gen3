## Real bugs
- [high][HIGH] tagText.ts:36-37 — `PURE_TAGS_RE` backtracks exponentially, because `/` is in both the token charset and the separator class. Trigger: a text node, or the textContent of an `<a>`/`<button>`, such as `"#a/#a/#a/…(n times) x"`. Measured in node: n=20 takes 21 ms, n=22 takes 82 ms, n=24 takes 323 ms (about 4x per +2), so n≈32 (under 100 chars) blocks for more than a minute. It is called for every queued node in grouping.ts:241/244 when `groupByBlock` is on (Google, the default). Outcome: one user comment can freeze any page for every Prism user. Fix: take `/` out of one of the two classes, or make the token possessive (an atomic-group workaround).
- [med][HIGH] translateLoop.ts:739-741, 785-787 — punctuation restore is wrong in both directions. (a) When the source had *any* leading or trailing whitespace, the translation's own leading punctuation is stripped: `"Are you sure? "` → es `"¿Estás seguro?"` is written as `"Estás seguro? "` (verified). The same happens to `«`, `「` and `¡`. (b) A source-language leading run is always re-imposed: es→en `"¿Qué pasa? "` becomes `"¿What's up? "`, and ja `「こんにちは」と…` becomes `「Hello," he said`, with mismatched brackets. Trigger: any text node next to inline markup, with an es/fr/CJK source or target. Not tested (no ¿/«/「 cases in translateLoop.test.ts). Fix: keep only the *whitespace* parts plus a leading `.`/`,`/`;` run, not every non-letter.
- [med][HIGH] attributeTranslator.ts:124-134 (enforced by test :86-92, :184-198) — `noteOriginal` keeps the first value ever seen. If the page later changes an attribute itself (aria-label/title toggles: "Play"→"Pause", "Open"→"Close"), `restore()` rolls it back to the stale first value and leaves the control's label lying about its state. translateLoop.ts:401-408 fixed exactly this for text nodes. The "first-wins" rule only exists to cover the next bug.
- [med][HIGH] attributeTranslator.ts:165, 176-180 — the write-back never checks that the attribute still holds the text that was *sent*. The comment at :174-175 says it handles that, but the code only checks null/connected. Trigger: the page sets V2 while T(V1) is in flight. Outcome: T(V1) overwrites V2. The queued V2 mutation then drains, reads the attribute *now* (T(V1)), and re-translates our own output, so V2 never appears. Fix: mirror `sentText` from translateLoop.
- [med][HIGH] attributeTranslator.ts:161, 263-271, 289-299 — a rejected `translateBatch` (remoteTranslator.ts:105 rejects on sendMessage failure or timeout) goes unhandled. In `start()` that means `startWatching()` never runs, so dynamic attributes are never translated for the rest of that cycle. `void drainPending()` also produces unhandled rejections. translateLoop and titleTranslator both catch this case.
- [med][HIGH] attributeTranslator.ts:226-233 — the attribute-change path uses the wrong predicate. `isNoTranslateNode(el)` skips the element's *own* changed attributes when it is a TEXTAREA/CODE/SVG/OPTION/icon element, but collectTextNodes.ts:322-333 says those elements' own attributes (a textarea placeholder, for example) must be translated. So a dynamic textarea placeholder is never re-translated. There is also no `hasNoTranslateAncestor` check, so an attribute change *inside* a `translate="no"` subtree does get translated. The initial walk never would have.
- [med][MED-HIGH] titleTranslator.ts:176-182, 192-206, 258-261 — there is no per-request generation or staleness check, only the boolean `active`. (a) start(fr) is in flight, then restore and start(de): the fr result lands with `active===true` and is applied, so the tab shows French. (b) Fast SPA chapter skips: the "Ch1" response lands after "Ch2"'s and is applied. Either way `current === translatedPageTitle` (:190) then suppresses any fix-up, so the title stays wrong. `start()` also installs the watcher even after a restore that landed mid-await (:259-260). attributeTranslator has the generation guard this lacks.
- [med][MED] translateLoop.ts:425, 1104, 1168 vs 1028-1029 — `wakeRoutine()` cancels the surfaced-error backoff timer and runs a tick at 0 ms. Trigger: provider broken (backoff 8-30 s) on a page that keeps mutating (ticker, chat). Outcome: one failing request per mutation or resweep instead of one per 30 s, which defeats the backoff's purpose.
- [low-med][HIGH] translateLoop.ts:1269 (and attributeTranslator.ts:307) — `restorePage` skips disconnected nodes, then clears the map. A recycled-pool node that is detached at restore time comes back still translated, on a page in the 'original' state, with no watcher running. Writing `.data` to a detached node is harmless, so the `isConnected` check should go. Related: the two-tick prune (:82-97, :1161) only covers detaches shorter than about 3-20 s. A pooled node that is off-DOM longer than that loses its restore entry for good. The comment at :1148-1160 overstates the fix.
- [low][HIGH] translateLoop.ts:257-266, 293-298, 1252 — `totalPieces` is fixed at the initial count, but `completedPieces` also counts nodes discovered later. On infinite scroll or SPA pages, done/total goes above 1. FloatingBubble.tsx:583 then hides the bar while the initial content is still pending. The comment's "won't overshoot" claim is false.
- [low][MED] translateLoop.ts:199, 198 — `missingResultAttempts` and `requeueAt` survive across cycles. A node that gave up in cycle 1 gets zero retries after a re-translate to another language.
- [low][MED] translateLoop.ts:674-678, 561-578 — a synchronous throw after `queue.splice` (from a listener inside `recomputeWorking`/`setWorking`, `getBatchingHint`, or grouping) drops the batch permanently: still dedupe-tracked, `lastSeenText` matches. The `finally` then re-arms at 0 ms, so a deterministic throw spins in a loop. Listeners run unguarded (:249, :287, :349).

## Risks
- translateLoop.ts:1027-1063 — the tail always re-arms. Idle and translated means a 2 s timer forever; a tick that runs while 'original' (orphaned timer) also re-arms every 2 s. Several sites (:577, :598, :1063) overwrite `translationRoutineHandle` without clearing it, which orphans timers. The generation guard keeps this harmless today, but it is fragile.
- grouping.ts:105-123 — `BLOCK_TAGS` has no NAV/HEADER/FOOTER/MAIN/ASIDE/UL/OL/TABLE/BODY/custom elements. All shadow-DOM text resolves to a `null` block, so consecutive nodes from unrelated components (or loose body text) are grouped into one multi-item piece. That is the same marker-scrambling risk points 3-5 exist to prevent.
- collectTextNodes.ts:192 — `translate="no"` is compared case-sensitively (the HTML value is case-insensitive), and a nested `translate="yes"` is ignored.

## Comment/code drift
- collectTextNodes.ts:172 says the config default for `translatePreTags` is false. :184 says omitted means translate (config default true, schema.ts:149). translateLoop.ts:110 and :1096 say omitting the getter skips `<pre>`. These are three contradictory statements.
- translateLoop.ts:338-341 says `consecutiveBatchFailures` "is reset on offline ticks". The offline branch (:595-600) doesn't reset it.
- translateLoop.ts:1197-1201 says the offline error "clears itself on the very next tick". It only clears after a batch with no genuine failure. After a long outage, a failing provider keeps showing "Offline" for up to 3 × 30 s.
- translateLoop.ts:1117 says "line ~464 below"; the call is at :805, above. :529-531 still describes `batchInFlight`, which no longer exists.
- translateLoop.ts:13-43 and many blocks: incident narrative ("Real bug, found via…") makes up most of the 1379 lines. Logic is hard to see and cross-references rot (above).

## Dead / duplicated / complexity
- translateLoop.ts:1321-1322 — `getTranslatedNodes` has no production caller (only a comment in mountHoverTooltip.ts:22).
- titleTranslator.ts:150-153, 159-165 — `suppressNextObserverTick` is effectively dead. After `document.title = text`, `textContent === text`, so the flag is never set, and the own-write guard really comes from `translatedPageTitle`. When it *is* set during `restore()` (no observer attached), it can swallow the next real title change.
- `HAS_LETTER` is defined 3× (translateLoop.ts:69, mutationWatcher.ts:67, grouping.ts:184), and the prune helper is duplicated (translateLoop.ts:82 vs attributeTranslator.ts:19). Small.

## Performance hot spots
- resweep.ts:54-56 + translateLoop.ts:1165 — a full `document.body` walk (isNoTranslateNode per element, a trim allocation per text node) runs every 1.5-10 s forever, at 1.5 s whenever anything changed, and 650 ms after every scroll stop (:71-77). A churning page stays at 1.5 s full walks indefinitely.
- translateLoop.ts:1341-1346 — `findOriginalTextForElement` is still O(N) per mousemove. Indexing by parentElement would make it O(1).
- attributeTranslator.ts:233 — any watched-attribute change re-walks the element's *entire subtree*, for example a `title` toggled on a large container.
- mutationWatcher.ts:88 — an O(depth) ancestor walk per added node, plus duplicate subtree walks when a parent and its child both appear in addedNodes.

## Test gaps
- No tests for target or source leading punctuation (¿ « 「), title responses arriving out of order or across restore+start, attribute `translateBatch` rejection, attribute change during flight, textarea placeholder changes, the PURE_TAGS_RE worst case, progress overshoot with late-discovered nodes, or restore of detached-but-pooled nodes.

## Strengths worth keeping
- Generation guards on the main loop (`cycleGeneration`, `inFlightGeneration`, `runningForGeneration`) and the structural "always schedule a successor" `finally`.
- The `sentText` stale-write check and `lastSeenText` recycle detection. WeakSet dedupe plus `queuedSet` keep membership checks O(1).
- Iterative, shadow-aware walks; block-straddle push-back with a starvation guard; viewport partitioning by block with memoized rects.
- Timing-free exported helpers (`pruneDisconnected*`, `shouldAutoTranslateOnLoad`) make the tricky parts directly unit-testable.
