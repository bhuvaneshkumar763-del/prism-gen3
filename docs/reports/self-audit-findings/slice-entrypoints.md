## Bugs
- [med][HIGH] content.ts:419-425 (vs 413-417, 343-398): manual translate never reaches same-origin iframes. `pageTranslate` is registered top-frame only, but `pageRestore` is in every same-origin frame and auto-translate-on-load does translate them. Trigger: page with a same-origin iframe (embedded comments, docs viewer), user clicks Translate (popup, bubble, context menu, shortcut), or changes target language on an auto-translated page. Outcome: iframe stays original, or stays in the OLD target language, so the page is half-translated. The known-gaps list doesn't mention this. Fix: register `pageTranslate` in sub-frames too, or relay through background.
- [med][MED-HIGH] background.ts:487-501: context menus are created only in `runtime.onInstalled`. That works for Chrome MV3, where menus persist. But Firefox and Orion (WXT default MV2, `persistent: true` per the comment at 303) don't persist menus from a persistent background page across browser restarts. Trigger: a Firefox user restarts the browser. Outcome: all three right-click items disappear until the next update. Signed Firefox builds ship (commit fed8806). Fix: `contextMenus.removeAll()` then create on every background start.
- [med][HIGH mechanism / MED trigger] background.ts:176: `frameLanguageDecisions` lives only in SW memory. Trigger: a same-origin iframe inserted more than ~30s after load (lazy embed, SPA), after the worker has gone idle and restarted. Outcome: the map is empty, the iframe polls ~9s (content.ts:364) and gives up silently on an auto-translated page. Fix: `storage.session` keyed by tabId.
- [low-med][HIGH] popup/App.tsx:104 + 428-437: `translated()` requires `status() !== 'busy'`. `onRestoreClick` sets busy, so the Show flips to the fallback Translate button, which reads "Translating…" during a restore. The "Restoring…" branch (436) can never render.
- [low-med][HIGH] popup/App.tsx:109, 487: `alwaysLangOn` uses an exact `includes`, and the toggle-visibility check uses an exact `!==`. `shouldAutoTranslateOnLoad` compares base tags (autoTranslateDecision.ts:76-80). Trigger: list has `pt` and the page detects `pt-BR`, or page `zh-CN` with target `zh`. Outcome: the toggle reads OFF while auto-translate fires anyway, or "Always translate from X" shows when auto-translate can never fire. Same class as the www/apex fix noted at 105-106.
- [low][HIGH] content.ts:343-398: the sub-frame poll's `sendMessage('getFrameLanguageDecision')` isn't wrapped in try/catch. Trigger: extension reloaded or updated with the page open (context invalidated), or the background throws. Outcome: unhandled rejection in the page console. Same class as commit 4aaabff.
- [low][MED] options/App.tsx:446-476 + 117-130: provider inputs save on `change` (blur) without awaiting, and background reads its own configStore mirror, updated via `storage.onChanged`. Trigger: type an API key, then click "Test translation" directly. Outcome: the test can run against the old or empty key ("needs setup") on the first click. Same caveat for popup/App.tsx:240-242, whose comment says the write "has to have landed first", but landing in storage doesn't mean the background mirror has updated.
- [low][HIGH] background.ts:225-232: the failure badge is global (no tabId), and overlapping timers let the first timeout clear a newer '!' early.
- [low][LOW] background.ts:543-545: if Chrome reports `status:'loading'` for same-document (pushState) navigations, the decision is deleted and never re-reported (content script doesn't re-run). Iframes created after an SPA route change then never inherit.

## Security / privacy
- [med][HIGH] background.ts:306, 254-272: `prefetchGoogleAuthKey()` runs on every worker start, whatever provider is configured. Every top-level page load wakes the SW (content.ts:330 report, plus detectTabLanguage). Outcome: a user who picked a self-hosted LLM or Cloud Translate, often for privacy, still has the extension fetching translate.googleapis.com roughly every 20 minutes of browsing (each time the stored key goes stale), without ever translating. Gate it on `pageTranslatorProvider === 'google'`.
- [low][HIGH] wxt.config.ts:41-48: the comment says `activeTab` avoids broad host access and that `<all_urls>` is "a deliberate later-session decision". But content.ts:56-64 already uses `matches: ['*://*/*']` + `allFrames`, which is an install-time all-sites grant. `activeTab` is redundant and the comment misstates the permission footprint.
- [low][LOW] wxt.config.ts:55: no host_permissions. On Firefox MV2, content-script matches don't grant background cross-origin fetch, so a user-configured LLM base URL (e.g. a local server) works only if it sends CORS headers. Worth verifying on Firefox.
- Good: every `onMessage` handler checks `isTrustedSender`. The incognito cache bypass (background.ts:356) is correct. The `openOptionsPage` section is whitelisted by regex (522).

## Strengths worth keeping
- The cache layer is strictly best-effort: read, parse and write failures all degrade to a miss or no-op. getMany/setMany batching, and the reply isn't blocked on the write.
- The provider instance is memoized with a config fingerprint, so tabs share one rate limiter.
- Popup content-script calls go through `withTimeout` and `allSettled` (loadPageStatus). Options writes are optimistic with rollback and a visible error.
- The cross-origin sub-frame early bail (content.ts:93-99), plus origin-stamped frame decisions.
