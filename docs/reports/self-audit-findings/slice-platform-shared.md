## Real bugs

- [high][HIGH] src/shared/config/listMutations.ts:28-30,112-118 (+96-110) — the membership test is www/apex-aware and normalizes stored entries (`siteListIncludesHostname`, :89-94), but add/remove use plain exact `includes`/`filter` (`withAdded`/`withRemoved`). So the toggle state and the mutation can disagree. Trigger: `neverTranslateSites: ['example.com']` (added in Settings, or a raw `BBC.com` from an older build or a backup), user is on `www.example.com`. The popup's `neverSiteOn` (entrypoints/popup/App.tsx:108) shows ON. Clicking it calls `removeSiteFromNeverTranslate(snapshot,'www.example.com')`, which does nothing. Outcome: from the popup or bubble the rule can't be removed, and the toggle stays ON. Same mismatch for `addSiteToAlwaysTranslate('www.example.com')`: it leaves `example.com` on the never list, so both lists hold the site. `autoTranslateDecision.ts:68` checks never first, so the "always" rule does nothing while both toggles show ON. This is the exact state the file's header says it prevents. No test covers it (listMutations.test.ts only tests `siteListIncludesHostname` with www).
- [med][HIGH] src/shared/config/listMutations.ts:120-136 — the same class of bug for languages and for the `hostname` argument. `addLangToAlwaysTranslate('pt-BR')` leaves `'pt'` in `neverTranslateLangs`, but the decision compares by base tag with never checked first (autoTranslateDecision.ts:79-80), so the new "always" rule does nothing. The `hostname` argument on :125/:134 is neither normalized nor apex-matched, so the cross-list cleanup the popup relies on (popup/App.tsx:373) misses `www.` variants.
- [med][HIGH mechanism / MED impact] src/platform/cache/translationCache.ts:122,370 — `runningTotalBytes` is per instance, and Settings has its own instance (options/App.tsx:163 `translationCache.clear()`), separate from the background's. Trigger: Clear cache in Settings while the background context stays alive (always on Firefox's persistent MV2 page; on Chrome, while the service worker is warm). Outcome: the background keeps its pre-clear total (a full cache sits near 5 MB), so its effective budget falls to about `5MB − staleTotal` and each write evicts real, freshly cached entries until the worker restarts. The header comment (:139-141) admits the cross-context issue but only handles it on reopen. No test uses two instances.
- [med][MED] translationCache.ts:328,339,356 — eviction loses updates. `remaining` comes from the total read before the eviction transaction, and `runningTotalBytes = remaining` overwrites any `setMany` delta credited in between (:313). background.ts:466 fires `setMany` without awaiting it, from several frames and ticks at once, and over budget is the normal state of a full cache. Outcome: the count slowly under-counts, so real on-disk size drifts past the budget over a long-lived context. Two overlapping evictions also over-evict.
- [low][MED] translationCache.ts:171-175 — `withDb` retries on any error, not only a closed connection, and drops the old connection without `close()`. Each such error leaks a connection, and its later `close` listener throws away the healthy connection and the count. There's also no `onversionchange`/`onblocked` handler (:70-83), so a future `DB_VERSION` bump will hang behind any context still holding an open connection.
- [low][MED] src/platform/configStore.ts:89 vs :73-78 — `onChanged` is registered before `initConfig` finishes. A write from another context that lands between the `getAll()` snapshot and the adopt loop is applied, then overwritten by the stale snapshot. The window is widest on the migration path (two awaits at :47,:56). `set()`/`setMany()` (:163-185) also change `state` before persisting and don't roll back on failure.
- [low][LOW] src/shared/languages.ts:66-68 — `baseLanguageTag` treats zh-CN and zh-TW as the same language. Trigger: target zh-TW on a Simplified page. Outcome: auto-translate is skipped as "same language", and `translationDirection` returns null.
- [low][LOW] originalLanguageTracker.ts:233-236 — `start()` memoizes one detection for the life of the content script, so an SPA route change into another language keeps the first page's language.

## Security / privacy / CI

- [med][HIGH] .github/workflows/release.yml:31,57-59 — `actions/checkout` keeps its default `persist-credentials: true`, which writes a `contents: write` GITHUB_TOKEN into `.git/config`. `npm ci` then runs every dependency's lifecycle scripts, plus `postinstall: wxt prepare`. Any compromised transitive dependency can push commits/tags or replace release assets. Fix with `persist-credentials: false`. All actions are pinned to mutable tags (`@v4`), not SHAs.
- [low][MED] release.yml:105 — `npx --yes web-ext@10.7.0` pins only the top-level package. Its transitive dependencies are resolved fresh, outside the lockfile, while `WEB_EXT_API_KEY/SECRET` are in the environment. ci.yml has no `permissions:` block, so the token's scope depends on the repo default.
- [low][HIGH] .github/workflows/fetch-signed-xpi.yml:39 vs scripts/fetch-signed-xpi.mjs:13-14,94 — the script documents exit 2 as "not an error, just not ready", but the step has no handling for it, so the run shows as a failure. `gh release upload --clobber` also leaves the unsigned zip next to the signed .xpi.
- [low][HIGH] src/platform/messaging/protocol.ts:161-182, remoteTranslator.ts:86-91 — `isTrustedSender` is described as blocking other extensions. In fact, a foreign `runtime.sendMessage(ourId)` arrives at `onMessageExternal`, never `onMessage`, and `tabs.sendMessage` only reaches the sender's own content scripts. The check is harmless defense-in-depth, but the "security fix" story overstates it. A future auditor may trust it for a threat it doesn't address.
- [low][MED] src/platform/diagnostics.ts:14-18 — redaction only matches keys ending in `ApiKey`. A credential inside `llmBaseUrl` (`https://user:token@…`, `?key=`) appears in the "redacted" config. migrations.ts:46-50 deliberately leaves the orphaned `libreTranslateApiKey` in storage forever. backup.ts:34-67 imports a partial file without showing what changes, so a crafted file that sets only `llmBaseUrl` sends the user's existing `llmApiKey` to another host (social engineering). Plain-text keys in exports are known and warned about in the UI.

## Guard scripts: do they enforce what they claim?

- [med][HIGH] scripts/check-engine-purity.mjs:20,36 — confirmed by running it on fixtures: these all pass: `import … from '../platform/messaging/protocol'` from src/shared (pulls in browser APIs transitively), `import '#imports'`, and WXT's auto-imported `storage.getItem(...)`. WXT auto-imports are on (no `imports:` override in wxt.config.ts), so `storage`/`createShadowRootUi` etc. need no import and no `browser.` prefix. `@webext-core/*`, `require`, and side-effect `import 'wxt/…'` (no `from`) aren't matched either. Fix: add `platform/`, `#imports` and `@webext-core` to the import pattern, or use `imports: false` for src/.
- [med][HIGH] scripts/check-solid-reactivity.mjs:69 — confirmed with a fixture: `const label = () => configStore.get('x')` used as `{label()}`, and `createMemo(() => configStore.get('x'))`, both pass. Both are the same non-reactive bug. The guard also only scans `configStore.`: a store passed in as a prop, or `readListsSnapshot(configStore)` inside JSX, escapes it.
- [low] check-bundle-size.mjs:28 — measures only the Chrome total, not per bundle (the zod tripling it describes was a per-bundle duplication problem), and never checks Firefox. None of the guard scripts, nor fetch-signed-xpi's exported `amoVersionFor`/`looksSigned`, have tests. `amoVersionFor` duplicates wxt.config.ts:15-16.

## Strengths worth keeping

- validate.ts's mapped type `{[K in ConfigKey]: Validator<Config[K]>}` keeps schema and validators in compile-time sync. Migrations are pure and unit-testable. The validate-or-keep rule applies on both the init and live paths.
- The cache handles dead connections (close listener plus a single retry), commits counter changes only after `oncomplete`, and leaves the recency touch unawaited.
- `withTimeout` is used on every cross-context wait.
- Release hygiene: gated on CI `workflow_run` for `push` only, builds the verified `head_sha`, keeps secrets in step-scoped env, validates VERSION before use in a filename, and pins web-ext.
