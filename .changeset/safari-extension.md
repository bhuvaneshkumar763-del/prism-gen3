New platform: Safari (macOS + iOS/iPadOS). WXT already produces a `safari-mv2` build with no code changes (`npm run build:safari`), but Safari doesn't load a raw web-extension folder the way Chrome/Firefox do — since Safari 14 it requires the extension wrapped in a native app, built with Xcode. `safari/Prism/` is a real Xcode project generated by Apple's own `xcrun safari-web-extension-converter`, containing the exact same engine/UI code as the other two builds.

Both targets are concretely verified, not just assumed to work: `Prism (macOS)` builds and code-signs successfully with a real Apple Development certificate, and `Prism (iOS)` builds for the Simulator, installs, launches, and shows Prism's real icon plus Apple's own "turn on the extension in Settings" prompt — confirmed via an actual simulator screenshot. `DEVELOPMENT_TEAM` is baked into every build configuration so opening the project needs no manual signing setup (on a different machine/Apple ID, you'll need to pick your own team in Xcode's Signing & Capabilities tab — see `safari/README.md`).

One real compatibility gap found via Apple's own converter output, not guessed: it warns that persistent background pages aren't supported on iOS/iPadOS, and WXT's shared MV2 manifest (also used by Firefox) defaults to `background.persistent: true`. `npm run safari:sync` (which builds and then mirrors the web-extension output into the Xcode project) now forces `persistent: false` for the Safari copy specifically — universally, not just for iOS, since `entrypoints/background.ts` already assumes a background context that can be torn down and rebuilt on wake (the same model Chrome's MV3 service worker already requires), making this the more correct setting on macOS too.

`xcrun safari-web-extension-converter --rebuild-project` was tested and found to fully regenerate the whole Xcode project from scratch (discarding the baked-in signing team and any future native customization) rather than just refreshing resources — `scripts/sync-safari.mjs` does a plain, surgical directory mirror instead, confirmed to be the correct operation since the Xcode project's `Shared (Extension)/Resources` folder is an exact 1:1 copy of the WXT build output. `biome.json` excludes `safari/Prism/` (Xcode project internals, not JS/TS the linter should ever touch).

What this does *not* include, because it genuinely needs your own Apple account: a paid Apple Developer Program membership for real distribution/notarization, and App Store Connect submission. Enabling the extension in Safari also needs one real, unscriptable user click (Safari → Settings → Extensions) — by Apple's own design, not a gap in this setup.
