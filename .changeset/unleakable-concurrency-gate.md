"prism-gen3": patch
---

Fixed a real bug found via a live user report: on Orion Browser (iOS), translation would work exactly once per browser launch and then hang forever on every subsequent attempt, specifically on chapter pages of sangtacviet.vip when using that site's own built-in "translate to English via Google Translate" feature — never recoverable without fully quitting and reopening the browser.

Root-caused by reading the site's own shipped JavaScript directly: its chapter-level translate feature does a full `innerHTML` replacement of the entire chapter content container after fetching its own translation, destroying every existing text node and orphaning any Prism translation requests genuinely in flight for that content. `batchedHttpProvider.ts`'s shared `concurrencyGate` — a singleton living for the whole background-context lifetime — only returns a permit once its underlying `sendOnce()` promise settles, and `sendOnce()` relied entirely on `AbortController` to make `fetch()` reject after a timeout. WebKit (Orion's and iOS Safari's engine) has real-world cases where aborting a fetch doesn't reliably reject it once the response body is already streaming — exactly the shape of a response from a text-dense chapter page. If that happens even once, the gate permit is lost forever, and once enough leak, every future translate queues behind dead waiters indefinitely.

Fixed by giving `sendOnce()` an unconditional backstop: it now races the real fetch attempt against a plain `setTimeout`-based rejection that doesn't depend on `AbortController`/`fetch` cooperating at all, guaranteeing the concurrency gate can never leak a permit regardless of platform-specific fetch/abort behavior. Also made `background.persistent: false` apply to every MV2 build (previously only the Safari-wrapped app got this via `scripts/sync-safari.mjs`'s post-build patch) — `entrypoints/background.ts` already assumes a rebuildable-on-wake lifecycle, so this bounds the blast radius of any future undiscovered leak to one background-page lifetime instead of an entire browser session. Verified via a revert-and-confirm-fails regression test that reproduces the exact WebKit gap (a `fetch()` that never settles even after its `AbortController` fires) and proves a later, unrelated `translateBatch()` call still gets a free concurrency slot afterward.

Also fixes an unrelated, independent regression found while investigating: beta.55's always-on viewport-priority reorder could re-measure an entire large, continuously-churning queue on every single tick if new/changed nodes kept arriving faster than the tick could drain them — real, compounding main-thread cost on a text-dense, dynamically-updating page. Now throttled to at most once per 500ms once the queue exceeds `MAX_PIECES_PER_TICK`, while staying always-on (unthrottled) for the common smaller-page case beta.55 targeted. Also swapped `requeueChangedTextNode`'s O(n) `Array.includes()` duplicate-check for an O(1) `WeakSet`, closing the exact anti-pattern `dedupe.ts`'s own header comment already warns against.
