Cleanup, not a fix — labeled plainly since this repo's own discipline is to only claim what's actually verified: `google.ts`'s reflow-repair reconciliation loop awaited each simultaneously-needed repair one at a time (`final[index] = await repair(index)` inside a `for` loop) instead of together via `Promise.all`. This was investigated as a candidate explanation for a live-reported "translation hangs forever" bug (a chapter page with many grouped, reflow-prone pieces could in theory need many repairs in one tick), but testing it directly disproved that theory: `onPieceComplete` already dispatches every repair concurrently the instant its raw outcome is known, well before the old sequential loop even ran — so the loop was only ever collecting already-in-flight or already-resolved promises in array order, never actually serializing their wall-clock time. A revert-and-confirm-fails regression test confirmed this: it passes identically on both the old and new code, proving no observable behavior changed. Switched to `Promise.all` anyway as a safe, behavior-preserving simplification (and real robustness margin for the theoretical case where a repair isn't pre-dispatched by `onPieceComplete`), verified via the same test for correctness (multiple simultaneous repairs each resolve to the right value, not misassigned across indices).
