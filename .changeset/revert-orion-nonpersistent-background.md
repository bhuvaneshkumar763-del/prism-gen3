Reverted part of the previous release's fix, found via live user testing that showed the exact same "stuck spinning" symptom recurring on Orion (iOS) immediately after updating: `background.persistent: false` was applied to every MV2 build, not just the Safari-wrapped app. That's mandatory and correct for real Safari on iOS (Apple's docs flatly reject `persistent: true` there, and `scripts/sync-safari.mjs` still forces it independently) — but Orion, when the extension is loaded directly rather than through Apple's native Safari-Extension framework, implements its own background-page lifecycle, and beta.44 already root-caused and fixed a "stuck busy spinner forever on mobile" bug on this exact same site, tracing it to the background context dying mid-request under mobile memory pressure and permanently orphaning an in-flight message. Making the background page non-persistent for Orion specifically makes that exact failure mode more likely, not less, if Orion's own implementation doesn't correctly recognize a pending `fetch()`/message handler as a reason to stay alive the way Chrome's real MV3 service worker does. `background.persistent` is back to WXT's own MV2 default (`true`) for every target except the Safari-wrapped app, matching every release through beta.57. The unleakable-concurrency-gate fix from the previous release (the `sendOnce()` timeout backstop) is unaffected and stays in place — that part is independently correct regardless of background-page persistence.
